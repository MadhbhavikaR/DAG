# Architecture Decision Records

Use one ADR per significant architectural decision. Number records sequentially.

## Required format

1. Title and status (Proposed, Accepted, Superseded, or Rejected).
2. Date and decision owners.
3. Context and forces.
4. Decision drivers and constraints.
5. Options considered.
6. Decision and rationale.
7. Consequences (positive, negative and neutral).
8. Security, privacy, performance and operational implications.
9. Validation plan and revisit triggers.
10. References.

An ADR records a decision and its consequences; it is not a general design tutorial.
