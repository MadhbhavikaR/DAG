# Development

## Environment

Install Python 3.10+ and [uv](https://docs.astral.sh/uv/). Then run:

```bash
uv sync --all-groups
```

The dependency lock is generated by uv and should be committed when dependency changes are made. Use `uv lock` to update the lock and `uv sync --locked --all-groups` to validate/install the resolved environment.

## Quality checks

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

To apply supported lint and formatting fixes:

```bash
uv run ruff check --fix .
uv run ruff format .
```

Tests must mock network access. Never send tests to real Telegram accounts or production webhook endpoints.

## Adding an extension

1. Create `extensions/<extension-name>/`.
2. Keep extension implementation, example configuration, tests, and extension README together.
3. For a provider extension, implement `NotificationProvider.send(notification) -> bool`.
4. Inject provider instances into `NotifierService(config, providers=[...])`.
5. Keep platform-specific configuration and dependencies isolated from the core wherever possible.
6. Add tests for success, failed requests, timeout handling, and malformed configuration.

## Branch and release conventions

The active branch is `Notifier-Service`. Push tags using:

```text
<branch-name>_<major>.<minor>.<patch>
```

Example:

```bash
git tag Notifier-Service_0.1.0
git push origin Notifier-Service_0.1.0
```

The release workflow validates the tag and creates a GitHub Release. It does not publish a package to PyPI.
